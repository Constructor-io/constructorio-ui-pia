# Recommendations Pod

A recommendations pod shows AI-curated product suggestions, usually on a product page. It is three
things: a personalized **title**, a row of **products**, and short **options** for narrowing them
down, plus a free-text box for describing something else.

It asks no questions and makes no Q&A requests, so a retailer can use it **without PIA Q&A
enabled**. Nothing about the Q&A experience changes when you turn it on.

<Canvas of={RecsPodStories.Designed} />

> **Provisional data source.** The endpoint that returns a short title and refinement options is not
> deployed yet, so the pod currently reads the Q&A endpoint. That endpoint returns a long answer
> where the title belongs and questions about the product where the options belong. The
> `LiveApiToday` story in the sidebar shows exactly that. Every other story here supplies
> a stand-in client, so what you see is the designed appearance. When the endpoint lands, only the
> request changes; no prop, no callback and no class name moves.

## Turning it on

```jsx
<CioPia
  apiKey="YOUR_API_KEY"
  itemId="YOUR_ITEM_ID"
  itemName="YOUR_ITEM_NAME"
  displayConfigs={{ mode: 'recommendations' }}
  recsPodParameters={{ strategy: 'complementary_items' }}
/>
```

`type: 'modal'` still wins over the mode, exactly as it does for `conversation`. A pod is inline.

## `recsPodParameters`

<Markdown>
{`
| Prop           | Type            | Default                  | What it does |
|----------------|-----------------|--------------------------|--------------|
| \`strategy\`     | \`RecsStrategy\`  | \`'complementary_items'\`  | Which kind of recommendations to fetch |
| \`defaultTitle\` | \`string\`        | —                        | Last-resort title, used only when the API returns products but no title |
| \`showInput\`    | \`boolean\`       | \`true\`                   | Render the free-text box after the options |
| \`numResults\`   | \`number\`        | —                        | How many products to request |
`}
</Markdown>

`strategy` is the pod's identity, not a cosmetic flag. One product page can host two pods — "Pairs
well with" and "Similar items" — from the same component with different strategies:

<Markdown>
{`
| \`strategy\`                 | Means |
|----------------------------|-------|
| \`'complementary_items'\`    | Goes well with this |
| \`'alternative_items'\`      | Similar to this |
| \`'bestsellers'\`            | Popular in the catalog |
| \`'bundles'\`                | Sold together |
| \`'buy_it_again'\`           | The shopper has bought it before |
| \`'recently_viewed_items'\`  | The shopper has looked at it before |
| \`'visually_similar_items'\` | Looks like this |
`}
</Markdown>

## What the pod shows, and when

Most of the copy comes from the API, including the copy for a shopper with no history and for a
request with no exact match. The API decides those cases and sends its own title with its own
products, in its normal response shape, so the library never picks between them.

<Markdown>
{`
| Situation | Title | Products | Options | Input |
|-----------|-------|----------|---------|-------|
| Nothing has come back yet | "Adapting recommendations to your preference" | placeholders | placeholders | placeholder |
| A refinement is in flight | "Adapting recommendations to your preference", faded in | placeholders | placeholders | disabled |
| A response arrived | from the API | from the API | from the API | idle |
| The agent rejected what was submitted | held | held | held | red border, message underneath |
| The response is degraded but has products | "Best selling products" | from the API | from the API | idle |
| The request failed and products are on screen | "Best selling products" | the ones already on screen | held | idle |
| The request failed and nothing is on screen | — | — | — | — · **the pod renders nothing** |
`}
</Markdown>

<Canvas of={RecsPodStories.Refining} />

Only the products and the options ever become placeholders. The refinement prompt holds still and
the products keep the height they had, so nothing on the page moves up or down while a request is in
flight.

The title is the one thing that does change, and it fades in over 200ms rather than snapping, so the
pod visibly reacts to what the shopper asked for. This is a fade-in on the arriving title, not a
cross-fade: React removes the outgoing text in the same frame, so there is nothing left to fade out.
The animation is dropped entirely under `prefers-reduced-motion`.

## The pod can render nothing at all

**Once a request has settled with no products, the pod renders no markup whatsoever** — not an empty
shell, not a message. Whatever the retailer already had in that slot shows through instead.

This is deliberate, and it is the one behavior worth knowing before you integrate: if you are
looking for a pod that is not there, a settled response with no products is the reason. A failure on
a *later* request behaves differently — the products already on screen stay, under "Best selling
products".

## Errors

The pod never shows a warning panel. There are two failure appearances and nothing else:

- **The agent rejected what was submitted** — a red border on the input with a message underneath
  it, and the response on screen untouched. Only the input changes, because only the input was
  wrong. The message clears on the next refinement.
- **Anything else** — the title becomes "Best selling products" over whatever products are
  available, or the pod renders nothing if there are none.

<Canvas of={RecsPodStories.UnsupportedRequest} />

To act on a failure yourself, read the `error` render prop: it is an `AgentRequestError` and carries
a `status`. See
[Component Overrides](./?path=/docs/components-ciopia-componentoverrides--docs#reading-the-error-render-prop).

## Translations

Five keys belong to this mode. They are the strings the API cannot supply, because in those
situations there is no usable response to read from:

<Markdown>
{`
| Key | Where it appears |
|-----|------------------|
| \`"Adapting recommendations to your preference"\` | While a request is in flight and nothing is on screen yet |
| \`"Best selling products"\` | The request failed, or came back degraded |
| \`"Unsupported request, try a different feature."\` | Under the input, when the agent rejects what was submitted |
| \`"Not what you're looking for? Try:"\` | The refinement prompt, only when the API sends none of its own |
| \`"Describe something else..."\` | The refinement input placeholder |
`}
</Markdown>

The refinement input has its own placeholder key, separate from Q&A's `"Ask anything"`, so
translating one does not change the other.

## Not in this version

- Per-product "why we picked this" explanations
- Thumbs up / down feedback on the pod
- Selecting more than one option at a time — refining replaces the whole response

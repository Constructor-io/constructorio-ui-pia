# Checkout Guide

## Overview

Pass `checkoutTriggers` to render checkout buttons inside the PIA widget, so a shopper can buy straight from the answer.

Triggers render in `default` mode only — `recommendations`, `conversation` and the modal ignore the prop for now.

The PIA UI Library renders the buttons and nothing else. You decide how the flow renders (inline, modal, or routed) and where its provider sits in your tree.

## Pre-requisites

You don't have to, but we recommend using our checkout library: [`@constructor-io/constructorio-ui-checkout`](https://github.com/Constructor-io/constructorio-ui-checkout)

The example below uses it.

```bash
npm install @constructor-io/constructorio-ui-checkout
```

## Setup

```tsx
import { CioPia } from '@constructor-io/constructorio-ui-pia';
import {
  CheckoutFlowProvider,
  useCheckoutFlow,
  CheckoutStripeStep,
  CheckoutFulfillmentStep,
} from '@constructor-io/constructorio-ui-checkout';

// 1. Mount the provider once at your app root.
export default function App() {
  return (
    <CheckoutFlowProvider
      steps={[{ id: 'payment' }, { id: 'complete' }]}
      onCreateSession={async ({ cart }) => {
        const res = await fetch('/api/checkout-session', {
          method: 'POST',
          body: JSON.stringify({ items: cart }),
          headers: { 'Content-Type': 'application/json' },
        });
        return res.json(); // { clientSecret, publishableKey }
      }}>
      <ProductPage />
      <CheckoutModal />
    </CheckoutFlowProvider>
  );
}

// 2. Start the flow from a trigger.
function ProductPage() {
  const flow = useCheckoutFlow();

  return (
    <CioPia
      apiKey='YOUR_API_KEY'
      itemId='prod_123'
      itemName='Wireless Headphones'
      checkoutTriggers={[
        {
          id: 'buy-one',
          label: 'Buy Now — $129',
          onTrigger: () => {
            flow.setCart([{ id: 'prod_123', quantity: 1, amount: 12900 }]);
            flow.start();
          },
        },
      ]}
    />
  );
}

// 3. Render the active checkout — modal, inline, or a route.
function CheckoutModal() {
  const flow = useCheckoutFlow();
  if (flow.state.status !== 'active') return null;
  return (
    <Modal onClose={flow.reset}>
      <CheckoutStripeStep id='payment' />
      <CheckoutFulfillmentStep id='complete' />
    </Modal>
  );
}
```

## `CheckoutTrigger` Prop

One entry per button. Add more for parallel paths (Buy 1 / Buy 2, save 25%).

```ts
type CheckoutTrigger = {
  id: string;
  label?: string;
  disabled?: boolean;
  triggerWhen?: (state: CioPiaRenderProps) => boolean;
  renderButton?: (props: {
    onClick: () => void;
    label: string;
    disabled?: boolean;
    id: string;
  }) => ReactNode;
  onTrigger: (state: CioPiaRenderProps) => void;
};
```

<Markdown>
  {`
| Prop | Required | Description |
|------|----------|-------------|
| \`id\` | yes | Stable identifier. Used as the React key and passed to \`renderButton\` |
| \`onTrigger\` | yes | Fires on click with the current render-props snapshot — seed the cart and start your flow here |
| \`label\` | no | Button text. Defaults to the translated \`"Checkout"\` |
| \`disabled\` | no | Disables the button, and is passed through to \`renderButton\` |
| \`triggerWhen\` | no | Re-evaluated every render; return \`false\` to hide the button. Defaults to always visible |
| \`renderButton\` | no | Replaces the default button. Receives \`{ onClick, label, disabled, id }\`; styling becomes yours |
`}
</Markdown>

```tsx
// Hide until an answer has been shown.
triggerWhen: (state) => !!state.currentAnswer;

// Use your own button.
renderButton: ({ onClick, label, disabled }) => (
  <MyButton onClick={onClick} disabled={disabled}>
    {label}
  </MyButton>
);
```

PIA does not reset your checkout flow — call `flow.reset()` from your own close handler.

For the full checkout API, see the [Constructor.io Checkout Library](https://github.com/Constructor-io/constructorio-ui-checkout).

# Component Overrides

The `componentOverrides` prop lets you replace any sub-component with your own custom React component using render props.

Every override receives the same props as the default component, so you have full access to the data.

## Override Hierarchy

The full list of overridable components:

<Markdown>
{`
| Path                              | Props Type                        | Description              |
|-----------------------------------|-----------------------------------|--------------------------|
| \`reactNode\`                       | \`CioPiaRenderProps\`               | Entire PIA component     |
| \`answer.reactNode\`                | \`AnswerRenderProps\`               | Answer text display      |
| \`suggestedQuestions.reactNode\`    | \`SuggestedQuestionsRenderProps\`   | Suggested questions list |
| \`disclaimer.reactNode\`           | \`DisclaimerRenderProps\`           | Disclaimer text          |
| \`feedback.reactNode\`             | \`FeedbackRenderProps\`             | Feedback controls        |
| \`loading.reactNode\`              | \`LoadingRenderProps\`              | Loading state            |
| \`carousel.reactNode\`             | \`CarouselRenderProps\`             | Entire carousel          |
| \`carousel.content.reactNode\`     | \`CarouselRenderProps\`             | Carousel content area    |
| \`carousel.item.reactNode\`        | \`CarouselItemRenderProps\`         | Individual carousel item |
| \`carousel.item.productCard\`      | \`ProductCardOverrides\`            | Product card sub-components |
| \`carousel.previous.reactNode\`    | \`CarouselRenderProps\`             | Previous button          |
| \`carousel.next.reactNode\`        | \`CarouselRenderProps\`             | Next button              |
`}
</Markdown>

## Custom Answer

Replace the answer display with your own component. Receives `{ text: string }`.

By default, the answer component renders `text` using `renderMarkdown`, which parses Markdown and sanitizes the output with DOMPurify. When overriding, use `renderMarkdown` to preserve this behavior. You can also pass `sanitize` to customize DOMPurify's sanitization (e.g. allow specific URI schemes like `sms:` or `tel:`). See the [Utilities](?path=/docs/general-utilities--docs) page for details.

<Canvas of={OverridesStories.CustomAnswer} />

```jsx
import { renderMarkdown } from '@constructor-io/constructorio-ui-pia';

<CioPia
  apiKey="YOUR_API_KEY"
  itemId="YOUR_ITEM_ID"
  componentOverrides={{
    answer: {
      reactNode: ({ text }) => (
        <div
          className="cio-pia-answer"
          dangerouslySetInnerHTML={{ __html: renderMarkdown(text) }}
        />
      ),
    },
  }}
/>
```

## Custom Suggested Questions

Replace the suggested questions list. Receives `{ questions, onQuestionClick }`.

<Canvas of={OverridesStories.CustomSuggestedQuestions} />

```jsx
<CioPia
  apiKey="YOUR_API_KEY"
  itemId="YOUR_ITEM_ID"
  componentOverrides={{
    suggestedQuestions: {
      reactNode: ({ questions, onQuestionClick }) => (
        <div className="my-questions">
          {questions.map((q) => (
            <button key={q.value} onClick={() => onQuestionClick(q.value)}>
              {q.value}
            </button>
          ))}
        </div>
      ),
    },
  }}
/>
```

## Custom Loading

Replace the loading state shown while an answer is being generated. Receives `{ skeleton }`, the default shimmer node, so you can reuse it in your own layout.

By default the component renders the shimmer skeleton. Provide `reactNode` to show your own loading indicator (e.g. "Thinking…" text) instead.

<Canvas of={OverridesStories.CustomLoading} />

```jsx
<CioPia
  apiKey="YOUR_API_KEY"
  itemId="YOUR_ITEM_ID"
  componentOverrides={{
    loading: {
      reactNode: () => <p>Cooking up an answer…</p>,
    },
  }}
/>
```

To keep the default shimmer alongside your custom content, render the `skeleton` node passed in the render props:

<Canvas of={OverridesStories.CustomLoadingWithSkeleton} />

```jsx
<CioPia
  apiKey="YOUR_API_KEY"
  itemId="YOUR_ITEM_ID"
  componentOverrides={{
    loading: {
      reactNode: ({ skeleton }) => (
        <div>
          <p>Thinking…</p>
          {skeleton}
        </div>
      ),
    },
  }}
/>
```

## Default Carousel

When an answer references products, the library renders a built-in carousel of default product cards — no configuration required. The examples below render the carousel directly with mock items, since the demo server does not return products.

<Canvas of={CarouselStories.Default} />


## Custom Product Card Sub-components

Instead of replacing the whole card, override individual parts of the default product card via `carousel.item.productCard`. Available slots: `image` (with `wishlistButton`, `badge`), `content` (`title`, `description`, `rating`, `price`), and `footer` (`addToCartButton`, `tags`). Each slot receives `ProductCardProps` (including `product` and handlers like `onAddToCart`).

<Canvas of={CarouselStories.CustomProductCardSubComponents} />

```jsx
<CioPia
  apiKey="YOUR_API_KEY"
  itemId="YOUR_ITEM_ID"
  componentOverrides={{
    carousel: {
      item: {
        productCard: {
          content: {
            title: {
              reactNode: ({ product }) => <p className="my-title">{product?.name}</p>,
            },
            price: {
              reactNode: ({ product }) => <span className="my-price">${product?.price}</span>,
            },
          },
          footer: {
            addToCartButton: {
              reactNode: ({ product, onAddToCart }) => (
                <button onClick={(e) => onAddToCart?.(e, product)}>Add to bag</button>
              ),
            },
          },
        },
      },
    },
  }}
/>
```

## Full Custom Layout

Override the entire component using the top-level `reactNode`. Receives all render props: `{ items, isLoading, error, currentAnswer, currentQuestion, displayedQuestions, handleSubmitQuestion, conversationHistory }`.

<Canvas of={OverridesStories.FullCustomLayout} />

```jsx
<CioPia
  apiKey="YOUR_API_KEY"
  itemId="YOUR_ITEM_ID"
  componentOverrides={{
    reactNode: ({ currentAnswer, displayedQuestions, handleSubmitQuestion, isLoading, items }) => (
      <div className="my-pia">
        <h3>Ask about this product</h3>
        {displayedQuestions.map((q) => (
          <button key={q.value} onClick={() => handleSubmitQuestion(q.value)}>
            {q.value}
          </button>
        ))}
        {isLoading && <p>Thinking...</p>}
        {currentAnswer && <p>{currentAnswer}</p>}
        {items?.map((item) => (
          <div key={item.id}>{item.name}</div>
        ))}
      </div>
    ),
  }}
/>
```

## Reading the `error` render prop

When a request fails, the `error` render prop holds an `AgentRequestError`. It extends `Error`, so
everything you already do with an error still works, and it adds one field:

<Markdown>
{`
| Field     | Type     | Meaning                                    |
|-----------|----------|--------------------------------------------|
| \`status\`  | \`number\` | The HTTP status code of the failed request |
| \`message\` | \`string\` | \`"Request failed with status <status>"\`     |
| \`name\`    | \`string\` | \`"AgentRequestError"\`                      |
`}
</Markdown>

`status` is there so you can tell one kind of failure from another without reading the message. It
applies to every mode, not just recommendations.

```jsx
import { AgentRequestError } from '@constructor-io/constructorio-ui-pia';

<CioPia
  apiKey="YOUR_API_KEY"
  itemId="YOUR_ITEM_ID"
  componentOverrides={{
    reactNode: ({ error, items }) => {
      if (error instanceof AgentRequestError) {
        // The request itself was rejected as unsuitable — nothing to retry.
        if (error.status === 422) return <p>Try asking something else.</p>;
        // Rate limited, or the service failed. A retry may work.
        if (error.status === 429 || error.status >= 500) return <p>Please try again shortly.</p>;
      }

      return <MyResults items={items} />;
    },
  }}
/>;
```

A network failure — offline, DNS — is a plain `Error` with no `status`, so check with `instanceof`
before reading the field.

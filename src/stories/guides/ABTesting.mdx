# A/B Testing

Your A/B system assigns cells; the library doesn't. Per shopper, pass the cell and whether it is the control.

Mount `CioPia` for every shopper in both arms:

```jsx
const cell = window.cnstrc?.testCell;

<CioPia
  apiKey='YOUR_API_KEY'
  itemId={itemId}
  itemName={itemName}
  abTest={{
    testCells: { constructorio: cell },
    isControl: cell === 'control',
  }}
/>;
```

<Markdown>
  {`
| | Test (\`isControl: false\`) | Control (\`isControl: true\`) |
|---|---|---|
| Renders | the widget | an invisible 1x1 placeholder |
| Requests | questions and answers | none |
| Events | the usual PIA events, with your cells | a view event, with your cells |
`}
</Markdown>

Both arms fire `product_insights_agent.view` through the same viewport tracking, so they're measured the same way.

## `testCells`

`{ [testName]: cellName }`, with your own test names. Each entry is sent as `ef-<testName>`, so a shopper in several tests carries every cell. Empty or non-string values are dropped.

`window.cnstrc.testCell` is a bare cell name, so label it with your test name as above. A `window.cnstrc.testCells` map can be passed straight through.

## `isControl`

Required. Pass `false` explicitly for the test arm: if it were optional, leaving it out would put everyone in the test arm and silently remove the control group.

## Your own `cioClient`

Set `testCells` on the client instead. `abTest.testCells` is then ignored, with a warning. `isControl` works the same.

```jsx
const cioClient = new ConstructorIOClient({ apiKey: 'YOUR_API_KEY', sendTrackingEvents: true, testCells: { constructorio: cell } });

<CioPia cioClient={cioClient} abTest={{ isControl: cell === 'control' }} … />;
```

## Verify

In the network tab, filter on `cnstrc`. Both arms should send `product_insights_agent_view` with `ef-<testName>=<cellName>`. The control arm should send no question or answer requests.
